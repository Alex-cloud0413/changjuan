# 长卷（LongShot）

一个完全在 iPhone 本机运行的长截图 App。仅支持 iOS 27 或更新版本，使用 ScreenCaptureKit 捕获用户主动滚动的画面；结束后自动去重、拼接、裁去顶部系统区域并保存到照片。1.1.0 新增双向滚动与手动跨页分段，Build 29 进一步放大、加粗控制中心三笔标志，保持桌面 App 图标不变。Build 29 已于 2026-10-06 替换原 Build 28 并重新提交 App Store 审核，当前「正在等待审核」，尚未替换公开分发版本。

源码使用独立私有仓库 [Alex-cloud0413/changjuan](https://github.com/Alex-cloud0413/changjuan)；不纳入 `life-os-workspace`。安装包、签名材料、测试录屏和临时输出不进入 Git。

当前产品为 iOS 27 专用体验：控制中心开始不跳 App、立即结束、快速整理、保存后可预览。默认启用 `LONGSHOT_SCREEN_CAPTURE_KIT`，使用 Xcode 27 RC 构建。工程与安装包已移除 ReplayKit Broadcast Upload / Setup UI 扩展；旧源码只作为未引用的历史文件保留。

## 首次设置

1. 打开控制中心并进入编辑状态。
2. 轻点「添加控制」，搜索并添加「长卷」。
3. 如果 iPhone 有操作按钮，也可以在「设置 → 操作按钮 → 控制」中选择「长卷」。
4. 打开长卷时允许完成提醒；若之前拒绝，可以点「完成预览提醒设置」自行开启通知和横幅。不会代替用户修改通知设置。

iOS 不允许 App 自动把控制放入控制中心，因此这一步需要由用户设置一次。也可以直接打开 App，轻点「开始收卷」。

## 日常使用

1. 在微信、淘宝、浏览器或其他目标 App 停在想要的起点，打开控制中心，轻点「长卷」。
2. 控制按钮请求后台执行，显示 Apple 的「Share Entire Screen（共享整个屏幕）」确认，不主动打开长卷；冷启动与热启动均以真机验证结果为准。
3. 确认共享后停在原处，等顶部面板收起，再缓慢向上、向下或往返滚动，保持相邻画面有重叠；同一页会按实际上下顺序去重拼接。先滑走会使遮住的起始内容无法补回。
4. 若需要接另一页，长按灵动岛重新展开，点「接下一页」暂停采集，切换到新页面后再次长按灵动岛，再点「继续」。也可在控制中心预先添加「长卷 · 接下一页」，第一次点暂停，切换后再点继续，不用返回 App。该控制仅在采集中可用。每段内部按上下顺序拼接，不同页面按采集顺序连接，中间有细分隔带。不要在未暂停时直接跨页。
5. 到达想要的终点后，长按灵动岛重新展开并点「完成」，或再次打开控制中心轻点「长卷」。
6. 捕获会立即结束并开始拼接，没有人为设置的固定等待时间。结果保存到照片后，长卷内会浮出可点击的缩略图；关闭提示不会删除图片，也不会每次打开 App 都重复弹出。若用户允许通知，还会请求系统显示带缩略图的完成提醒；其他 App 上的横幅由系统通知设置和专注模式决定。

Apple 的系统确认无法由第三方 App 跳过。录制只有在用户明确操作后才会开始，iOS 会持续显示录制状态；长卷不保存麦克风、App 音频或相机内容，也不会把任何画面上传到服务器。

## 构建与安装

当前开发与发布配置：

- Xcode 27 RC（Build 27A266a）
- iOS 27 SDK
- 最低系统版本 iOS 27.0（主 App 与所有扩展统一）
- 定版版本号 1.1.0，构建号 29（App Store 状态：正在等待审核）

用户于 2026-10-06 确认 Build 28 可用，并指定定版版本号为 1.1.0。主 App 与 Widgets 已重新构建为 1.1.0（Build 28），严格深度签名检查通过；「GYM iPhone」已原位覆盖更新，设备回读版本正确，普通启动成功，未卸载或清理原有数据。同日使用 Apple Distribution 签名上传并提交审核；继续沿用手动发布方式，审核通过后仍需发布。历史验证记录保留原实际测试版本，不回写为 1.1.0；本次发布记录见 [1.1.0 验证记录](Tests/Validation-1.1.0-build28.md)。

同日根据用户反馈修改控制中心符号，Build 29 已原位更新到「GYM iPhone」，通过资源渲染、签名与原有采集拼接回归检查。用户随后授权将本次修改同步至独立 GitHub 仓库，并替换 App Store 审核提交。Build 29 已正式重新提交，继续沿用手动发布方式；当前发布记录见 [Build 29 发布验证](Tests/Validation-1.1.0-build29.md)。新版本使用 `v1.1.0-build29` 标签；原 `v1.1.0` 标签保留 Build 28 历史，不强制移动旧标签。

用 `/Applications/Xcode-27-RC.app` 打开 `LongShot.xcodeproj`，选择 `LongShot` scheme 和目标 iPhone 后运行。主 App 启用 `screen-capture` 后台模式；自定义控制使用在主 App 进程后台执行的 `LiveActivityIntent`，等待系统选择和 stream 启动确认，不自动同意录屏权限。

主 App 的 Bundle Identifier 为 `com.gaoyiming.longshot.private`；控制中心与实时活动扩展为 `com.gaoyiming.longshot.private.Widgets`。两个组件使用同一个 App Group：`group.com.gaoyiming.longshot.private`。

## 当前边界

- 针对竖屏、同一页面内有连续重叠内容的上下滚动优化。快速跳跃、任意动画及缺少重叠的画面不能保证恢复。
- 灵动岛改为紧凑单行动作，不再持续显示帧数；大字号会自动分行。iOS 决定展开与收起时长，App 不承诺在 0.5 秒内隐藏，也不能跳过 Apple 的共享确认。
- 本地检测启动共享面板及长卷黑红展开区域，尽量从后续清晰画面补齐被遮内容；从未出现过的清晰内容无法凭空恢复。检测是保守启发式，需真机确认不同外观下效果。
- 跨页使用「接下一页／继续」明确分段，不自动猜测页面切换。暂停期间不保存画面；新页恢复后立即采集，无第二次系统授权或固定倒计时。异常页会提示失败而不是静默丢弃。
- 长卷进入前台时暂停保存自己的界面，切到目标 App 后保存收到的画面，不再固定删除开头或末尾若干秒。
- 系统转场、控制中心与重复纹理仍可能影响匹配；不能保证所有 App、动画和任意滚动速度均成功。
- 完成按钮直接调用主 App 进程中的 SCK 协调器，先封住新帧，再停止系统 stream 并提交采集记录；没有固定结束等待，也不再删除最后若干帧。后台运行保护衔接到图片生成与保存。
- 固定在页面顶部或底部的导航栏会从拼接主体中裁掉；首尾仍保留少量上下文。
- 新录制会按设备顶部安全区域的保守比例裁去状态栏与灵动岛，并保留其下的应用导航。
- 淘宝等双列商品流、固定优惠条、视频、动画和自动轮播可能增加识别难度；关闭弹窗、暂停视频并保持匀速滚动通常会改善结果。
- iOS 的系统截图悬浮缩略图不向第三方 App 开放；长卷用 App 内预览与系统通知提供最接近的体验。
- 所有帧和输出均写入本机 App Group 容器，不使用服务器。
