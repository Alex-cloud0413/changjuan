# 长卷（LongShot）

一个完全在 iPhone 本机运行的长截图 App。仅支持 iOS 27 或更新版本，使用 ScreenCaptureKit 捕获用户主动滚动的画面；结束后自动去重、拼接并保存到照片。支持纵向或横向的双向滚动、手动跨页分段、可选保留状态栏、图标式极简首页和中英文切换；录制期间提前分析，减少结束后的整理等待。当前修正版为 1.1.3（Build 46），增强冻结列表格对齐；无法恢复的底部悬浮遮挡仅在验证完整行边界后输出部分结果，并明确提示及保留原始录制。首页右上角齿轮进入设置，默认仍为纵向、去状态栏。三步引导统一从「查看使用方法」进入，隐私政策入口位于引导页，保留完成预览和失败恢复。

源码使用独立仓库 [Alex-cloud0413/changjuan](https://github.com/Alex-cloud0413/changjuan)；2026-10-18 实时核对为公开仓库，本轮不改变其可见性，不纳入 `life-os-workspace`。安装包、签名材料、测试录屏和临时输出不进入 Git。

**公开版本：1.1.2（Build 42）；1.1.3（Build 46）正在准备发布。** 2026-10-20 实时回读 App Store Connect，1.1.2 已「可分发」。本轮用户授权将已安装的修正版推送并提交更新；Build 46 只在 Build 45 基础上调整发布版本号，功能源码不变。自动回归、真机算法回放、标准包安装与用户重新录制验收分别记录，不把上传或提交视为审核通过。修复证据见 [Build 45 本地验证](Tests/Validation-1.1.2-build45-local.md)，历史发布记录见 [Build 42](Tests/Validation-1.1.2-build42-release.md)。

当前产品为 iOS 27 专用体验：控制中心开始不跳 App、立即结束、快速整理、保存后可预览。默认启用 `LONGSHOT_SCREEN_CAPTURE_KIT`，使用 Xcode 27 RC 构建。工程与安装包已移除 ReplayKit Broadcast Upload / Setup UI 扩展；旧源码只作为未引用的历史文件保留。

## 首次设置

1. 打开控制中心并进入编辑状态。
2. 轻点「添加控制」，搜索并添加「长卷」。
3. 如果 iPhone 有操作按钮，也可以在「设置 → 操作按钮 → 控制」中选择「长卷」。
4. 打开长卷时允许完成提醒；若之前拒绝，可以在「查看使用方法」第 3 步点击「通知提醒设置」，自行开启通知和横幅。不会代替用户修改通知设置。

iOS 不允许 App 自动把控制放入控制中心，因此这一步需要由用户设置一次。也可以直接打开 App，轻点首页中央截图图标。首页左下角「中文」与右下角「English」可切换 App 的界面语言。

## 日常使用

1. 在微信、淘宝、浏览器或其他目标 App 停在想要的起点，打开控制中心，轻点「长卷」。
2. 控制按钮请求后台执行，显示 Apple 的「Share Entire Screen（共享整个屏幕）」确认，不主动打开长卷；冷启动与热启动均以真机验证结果为准。
3. 确认共享后停在原处，等顶部面板收起，再沿设置中的方向缓慢往返滚动，保持相邻画面有重叠。纵向按上下顺序、横向按左右顺序去重拼接。先滑走会使遮住的起始内容无法补回。
4. 若需要接另一页，长按灵动岛重新展开，点「接下一页」暂停采集，切换到新页面后再次长按灵动岛，再点「继续」。也可在控制中心预先添加「长卷 · 接下一页」，第一次点暂停，切换后再点继续，不用返回 App。该控制仅在采集中可用。每段内部按上下顺序拼接，不同页面按采集顺序连接，中间有细分隔带。不要在未暂停时直接跨页。
5. 到达想要的终点后，长按灵动岛重新展开并点「完成」，或再次打开控制中心轻点「长卷」。
6. 捕获会立即结束并开始拼接，没有人为设置的固定等待时间。结果保存到照片后，长卷内会浮出可点击的缩略图；关闭提示不会删除图片，也不会每次打开 App 都重复弹出。若用户允许通知，还会请求系统显示带缩略图的完成提醒；其他 App 上的横幅由系统通知设置和专注模式决定。

Apple 的系统确认无法由第三方 App 跳过。录制只有在用户明确操作后才会开始，iOS 会持续显示录制状态；长卷不保存麦克风、App 音频或相机内容，也不会把任何画面上传到服务器。

## 本地存储管理（1.1.2）

- 照片保存事务成功、成功标记落盘且记录完成后，在后台删除对应原始帧和 Analysis-v1 分析缓存；不更改输出图片的像素、尺寸或压缩参数，也不操作照片图库中的图片。
- 已保存的本地预览按保存时间保留最多 7 天、10 次、合计 100 MB（100,000,000 字节，含记录元数据），触及任一限制优先清理旧记录。正在显示的预览/缩略图以及通知附件发送中的记录暂时豁免，关闭或完成交付后重新检查。期限在下次清理触发时执行，不承诺 App 未运行时定时清理。
- 保存成功、空闲激活（含旧版升级后第一次打开）、关闭预览/缩略图触发检查。开始新的采集会取消仍在运行的清理，避免与采集争用磁盘；下次空闲/保存再处理。
- 保存失败、未保存、录制异常或无法确认安全性的记录不自动删除，可继续恢复。1.1.3 的底部遮挡部分结果也保留整次原始录制，直到用户手动「清理所有缓存」；通知及预览会明确提示未收录的底部行。因此 100 MB 是普通已保存预览的清理预算，不是整个 App「文稿与数据」的硬上限。
- 过期记录先原子移出可恢复记录列表，再删除文件；若进程中断，下一次检查继续删除已退役文件，避免旧结果被重新拼接并重复保存。失效通知被移除；已打开的过期通知会提示到系统照片查看。
- 相册删除与 App 私有缓存清理相互独立，不需要读取用户照片库。自动清理只处理确认保存成功的 App 私有副本，不能恢复已经从照片删除的图片。
- 设置中的「清理所有缓存」经明确确认后删除所有原始画面和 Analysis-v1，包括未保存/失败记录；无法再用这些原始画面重新整理。照片、已生成的本地预览和语言偏好保留。录制、整理和清理期间不可重复操作；手动删除先写持久标记，避免恢复流程误重试以及滞后预处理重建缓存。

测试与边界见 [1.1.2 本地验证](Tests/Validation-1.1.2-build36.md)。

## 截图设置（1.1.2）

- 首页仅增加 44 pt 触控区域的齿轮。原生设置页提供纵向/横向分段选项、保留状态栏开关和缓存清理。中英文同步，原有纸白配色与留白保持。
- 方向在每次录制开始时写入 manifest；更改偏好不重新解释旧记录。一次录制只能用一个轴，不支持横竖混合、斜向拼图或录制中旋转屏幕。横向模式首页显示轻量状态提示。
- 横向使用独立的较细采样匹配表格数字，仍直接从原始 JPEG 按像素合成，维持 0.94 输出编码；分析缓存缺失或轴不一致时回退重算。支持左右反向和往返、按手动分段顺序连接页面。静止的顶部/底部栏保留一次，移动列标题不会固定裁掉。
- 保留状态栏默认关闭；开启后保留实际捕获像素，可能包含录制指示。横向宽图的状态栏放在左上方一次，不重复或拉伸。仍过滤展开的遮挡面板；未拍到的干净内容不能恢复。
- 宽图预览按高度适配、可横向查看与缩放；纵向预览沿用适配宽度。
- 横向匹配针对重复列、小幅纵向拖动偏移和往返滑动增强；识别到固定悬浮控件组时保留一次，遮住的正文只从实际无遮挡的重叠画面恢复，不生成未采集到的内容。
- 设置的设计自查见 [Build 37 历史验证](Tests/Validation-1.1.2-build37.md)；最新回归与真机验收见 [Build 42 验证](Tests/Validation-1.1.2-build42-release.md)。

## 当前边界

- 针对同一屏幕方向、有连续重叠内容的单轴滚动优化。横向首轮验证使用竖持 iPhone 的宽表格场景；横持屏幕、极窄表格、大片空白及复杂冻结区域还需真机验收。快速跳跃、任意动画及缺少重叠的画面不能保证恢复。
- 灵动岛改为紧凑单行动作，不再持续显示帧数；大字号会自动分行。iOS 决定展开与收起时长，App 不承诺在 0.5 秒内隐藏，也不能跳过 Apple 的共享确认。
- 本地检测启动共享面板及长卷黑红展开区域，尽量从后续清晰画面补齐被遮内容；从未出现过的清晰内容无法凭空恢复。检测是保守启发式，需真机确认不同外观下效果。
- 跨页使用「接下一页／继续」明确分段，不自动猜测页面切换。暂停期间不保存画面；新页恢复后立即采集，无第二次系统授权或固定倒计时。异常页会提示失败而不是静默丢弃。
- 长卷进入前台时暂停保存自己的界面，切到目标 App 后保存收到的画面，不再固定删除开头或末尾若干秒。
- 系统转场、控制中心与重复纹理仍可能影响匹配；不能保证所有 App、动画和任意滚动速度均成功。
- 完成按钮直接调用主 App 进程中的 SCK 协调器，先封住新帧，再停止系统 stream 并提交采集记录；没有固定结束等待，也不再删除最后若干帧。后台运行保护衔接到图片生成与保存。
- 固定在页面顶部或底部的导航栏会从拼接主体中裁掉；首尾仍保留少量上下文。
- 默认按设备顶部安全区域的保守比例裁去状态栏与灵动岛；可在设置中开启保留状态栏。保留的是真实录制内容，不重绘系统状态。
- 淘宝等双列商品流、固定优惠条、视频、动画和自动轮播可能增加识别难度；关闭弹窗、暂停视频并保持匀速滚动通常会改善结果。
- iOS 的系统截图悬浮缩略图不向第三方 App 开放；长卷用 App 内预览与系统通知提供最接近的体验。
- 所有帧和输出均写入本机 App Group 容器，不使用服务器。
