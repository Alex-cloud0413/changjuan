# 长卷 1.1.2（Build 45）：真实失败复现与底部遮挡降级

## 范围与授权

只分析用户本轮明确授权的第二次失败录制（140 帧），原始画面及诊断产物仅保存在 Git 忽略的本地 Build 目录；不上传 GitHub 或 App Store。用户明确接受无法补齐的底部悬浮遮挡降级：保留上方完整可见的表格行、明确提示底部行未收录、保留原始录制。未授权对中间缺口、缺列或一般匹配失败静默丢弃内容。

候选版本 1.1.2（45），最低 iOS 27；主 App 与 Widgets 同版本。保留工作树此前全部改动。安装成功、自动化检查、用户真机验收、发布是独立状态，当前 `releaseReady=false`。

## 复现与实现

- 原 Build 44 在该录制的一对画面上因冻结边界残留的约 3 像素列名字形否定实际存在的正文重叠。修正仅排除已隔离滚动区的极窄边缘分析像素；独特正文边缘、明暗、分离区域、跨轴及可见列名矛盾检查继续有效，不按上一次位移猜测。
- 修正位移后，全段录制仍在底部悬浮层覆盖检查失败。冻结区右侧的可动视口几乎被多个固定按钮占满，部分内容从未被其他画面露出。不能靠生成像素、涂白或关闭覆盖校验恢复。
- 仅对已证明不可覆盖的底部悬浮带，在首／中／尾独立画面中寻找真实完整行分界，并重新渲染至该行。找不到完整边界或遮挡不在底部仍失败。固定页脚原样保留一次，源 JPEG、尺寸分辨率与 0.94 编码质量不变；只有获授权的底部行被省略。
- 重新渲染前释放首个大画布，避免同时持有两个完整输出。上下轻微漂移时裁切统一使用已注册坐标，避免重复扣减共同可见区。
- 部分结果标记在 Photos 保存之前持久化；完成通知、首页缩略提示和预览均显示「底部遮挡行未收录」。预览补充原始画面保留至手动清理的说明。重启恢复、延迟通知沿用同一标记。
- 此类会话不参与自动原帧删除或整体过期清理；用户确认「清理所有缓存」后仍可释放原帧及分析缓存，随后恢复普通预览保留规则。系统相册不受缓存操作影响。
- 正文候选相关计算改用 Accelerate 的双精度卷积和累计矩，同一原生像素候选范围、采样行及阈值，不删除候选换速度。与原标量公式逐候选核对，包括负位移、奇数宽度、重复纹理及无纹理。

## 验证记录

真实回放已生成 8983×2213 的单张图，95 帧有效／45 帧略过，部分结果标记为真；已查看输出，底部停在完整表格行，未留下连续重复按钮。源画面未改写。该结果不等于手机完成至相册的全流程验收。

首轮统一门禁在旧用例「底部无法覆盖必须失败」处停止；这是新授权的行为变化，未将失败报告覆盖。用例改为要求部分结果标记、完整列宽、真实行边界、逐像素内容与原始文件不变，并保留无重叠／歧义／中间遮挡仍拒绝的反例。扩展后又检出上下轻微漂移下的重复裁切，修正后重新执行门禁。历史失败证据保留于 `Build/regression-SWDg7w/` 及本地专项日志。
