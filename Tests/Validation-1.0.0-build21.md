# Build 21 验证记录

日期：2026-09-06。状态：代码检查通过、已安装真机；跨 App 真机端到端结果待用户复测，不可提交审核。

## 原始失败证据

更新后从真机读取的本机元数据（不包含画面）显示：

- 2026-09-06 23:02:27–23:02:36（北京时间）的失败会话只保留 3 帧，错误为「没有识别到连续滚动内容」。
- 22:51:51 的上一会话保留 0 帧，记录仍停留在 capturing。
- 更早的成功会话及其图片记录仍在，覆盖安装未清除用户数据。

源码检查发现 Build 20 使用了应用内广播启动控制器，而不是系统级广播选择器；另有固定开头等待、删除最后 8 帧、粗略运动检测提前否决的问题。上述元数据支持采集链路异常，但无法单独证明每一次系统录制失败的具体原因。

## 修改范围

- 改为可见的 RPSystemBroadcastPickerView，首选长卷 Broadcast Upload Extension，保留手动轻点系统按钮与取消入口。
- 录制扩展持有采集与结束生命周期；通过 App Group 原子 JSON 传递请求、状态及按会话隔离的结束命令。
- 保存非长卷前台画面；不再固定删除开头或结尾时段，也不在采集层凭粗略运动阈值否决画面。
- 恢复后台会话、启动失败和新会话；后台停留超过原始请求期限时，先检查真实状态再判断超时。
- 控制中心优先读取录制扩展的新鲜状态，旧版残留 capturing 状态不再导致空结束命令。
- ReplayKit 的终止调用移出串行帧队列，防止同步回调重新进入该队列。
- App 导出最近五次会话的帧数、状态和错误，便于读取诊断；不会导出截屏内容。

## 复测步骤

1. 打开长卷，轻点「开始收卷」。
2. 确认系统面板显示「长卷录制」，轻点「开始直播 / Start Broadcast」，等待 Apple 倒计时结束；若未弹出面板，轻点页面上可见的系统录制按钮。
3. 切到微信或其他目标 App，向下滚动约 3–5 屏。
4. 从灵动岛轻点完成，或回到长卷结束并生成；记录收到的画面数和最终结果。
5. 上述成功后，再独立测试控制中心开始与结束。
