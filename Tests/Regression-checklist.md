# 长卷固定回归与发布门槛

适用于当前 iOS 27 ScreenCaptureKit 产品。历史 ReplayKit 的实现方式不作为目标，但其暴露的「误录屏、无反应、内容混入、丢帧」等用户问题继续覆盖。新增功能不得用减少画面、降低分辨率或压缩质量来换取速度。

## 一次运行

在长卷独立仓库执行（先自行启动专用 iOS 27 模拟器）：

```sh
DEVELOPER_DIR=/Applications/Xcode-27-RC.app/Contents/Developer \
node Tests/check-release-regressions.mjs --simulator <模拟器UDID>
```

统一入口串行执行测试，避免性能测试相互争抢 CPU；任一失败立即停止，以非零状态退出。日志、版本、代码指纹、固定旧版源码 SHA-256、结构化耗时和 Markdown 报告在 `Build/regression-*/`，不进入 Git。只构建未签名 Release 包及运行隔离测试，不连接真实手机、不安装 App、不触碰真实相册、录制或偏好，不推送和发布。

报告严格区分「源码契约」「实际生产方法＋系统桩」「原生算法/资源渲染」「真机端到端」。`automatedStatus=passed` 不表示真机通过；`physicalDeviceStatus=not_run`、`releaseReady=false` 默认保留，不能用自动化绿灯代替下表验收。后续源码改变须重新运行。

## 整理耗时验收

主指标是点击完成至相册写入完成的 `finishToSavedSeconds`，不是仅比较拼接函数。还要记录实际通知可见/可点击时间；通知发送函数返回不等于系统已显示横幅。`captureStoppedToSavedSeconds` 是替代观测值，不能改名冒充点击完成时刻。

| 测试组 | 固定输入与重复次数 | 记录 |
| --- | --- | --- |
| 模拟器算法防退化 | 1206×2622，90 帧/3 页，均预处理；1 次预热＋5 对交替执行旧版和新版 | 采样/选择/组装/渲染/总计中位数及样本 P95、命中帧数；每次帧数和图片字节一致 |
| 真机常用 | 同一台 iPhone、同一静态编号测试页、相同长度和操作，Release；单页/两页各至少 3 次 | 结束至保存、各阶段、帧数、页数、输出尺寸和张数、缓存命中、照片授权时间 |
| 真机压力 | 同条件 3/5 页、长页分页、快速结束、连续 5 次录制 | 上述指标，加后台时间到期、发热/掉帧和通知预览可用性 |
| 新功能组合 | 横向单页/多页，状态栏开/关，纵向复测 | 时长、完整性和画质同时验收；新功能没有旧版基线，不能报告相对提速 |

模拟器门槛：任一阶段/总耗时的中位数大于旧版 ×1.20＋0.15 秒，或样本 P95 大于旧版 ×1.35＋0.30 秒，视为回归并停止。五个样本的 P95 实际是最大值，只是噪声防护，不代表真实人群尾延迟。失败应检查机器负载并完整重测，不得随意提高门槛或只挑最快的一次。

真机旧功能门槛：相同内容、机型、系统、照片权限、电源/温度条件，至少 3 次中位数比验收基线增加超过 20% 且超过 1 秒，暂停发布并定位。任何漏内容、糊字、错误排序、明显重复或无法完成，均直接阻断，不因速度达标放行。缺少匹配基线只能记「待对照」，不是「性能无回退」。旧版 129 帧/2 页 5.88 秒是历史单次样本，不是所有录制的 SLA，也不能与不同输入直接算提速比。

每次测试须在下一次录制覆盖日志前导出本地 `LongShotCompletionTiming.json`；有条件同时导出 `LongShotProcessingEvents.json`。只读摘要命令：

```sh
node Tests/summarize-completion-timing.mjs <已导出的CompletionTiming.json> [已导出的ProcessingEvents.json]
```

缺字段保留为 `null`／`incomplete`，不补成零；非 Release、帧计数不一致、同会话后台到期或处理失败会报错。脚本不连接手机、不读取相册，不自动比较不同录制。原始日志只留本地忽略目录，提交验证记录只写必要统计。

## 验收记录模板与停止条件

每次版本建立验证记录：构建号、源码指纹、机型/系统、测试组、方向/状态栏、录制帧数/页数、输出张数/尺寸、完整性、结束到保存秒数、通知表现、证据位置、通过/失败/未测。对清缓存等不可撤销操作须单独确认并使用测试数据。

R01–R22 任一相关真机项目失败或未测，不标注「全部回归通过」。先修复再跑统一入口，再复测受影响真机链路。通过只说明上述范围和输入通过，不承诺所有第三方 App、任意滚动速度或所有设备都零缺陷。GitHub 与 App Store 发布仍需用户另行授权。
